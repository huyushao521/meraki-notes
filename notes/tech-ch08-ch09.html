Ch8 · LAN 安全

8.1 SGT 与 Adaptive Policy（微隔离）

SGT（Security Group Tag，思科文档也叫 scalable group tag）用于标识流量并执行安全策略， 类比 QoS 标记或 MPLS 标签：靠近源打标，逐跳按标签查表，而不是逐包全量检查。 SGT 封装在 IP header 内，以 Cisco MetaData (CMD) 为 EtherType（p.492）。

项要求
前提全部网络基础设施都必须支持 SGT，且所有设备至少需 advanced license
无线支持所有 Wi-Fi 5 Wave 2 / Wi-Fi 6 / Wi-Fi 6E 的 MR 与 CW AP，固件 MR27+
交换机支持MS390 需 MS14.33.1+；C9300-M 需 CS15.21.1+；C9300/L/X-M 需 CS16.7+
安全设备MX / Z3+，含所有可运行 MX18.1+ 的机型；MX84 因硬件限制不支持
SGT 取值1 – 65,519，但排除 2（保留给 Infrastructure）
与 ISE 关系可从 ISE 单向同步（SGT + 策略 + SGACL）；纯 Meraki 网络不需要 ISE；混合网络建议集成

启用与传播（三个开关都是手工的）：

  1. 启用：Organization > Adaptive Policy → Networks 标签 → 勾选 Adaptive Policy Disabled 的网络 → Enable。启用后交换机端口才会出现 peer SGT / adaptive policy group 配置项
  2. MS 端口：Switching > Switch Ports（Monitor）→ 选中接 AP/MS/MX 的端口 → Edit → Peer SGT Capable = Enabled，Adaptive Policy Group 选 2: Infrastructure
  3. MX 侧：Security & SD-WAN > Site-to-Site VPN > VPN Settings → Peer SGT Capable = Enabled；LAN 口须是 trunk 且 LAN Setting 为 VLANs。MX 固件 18.210+ 会额外显示 Adaptive Policy 下拉，也要选 2: Infrastructure
▲

MX 可通过 Auto VPN 在 WAN 上保留并传递 SGT，前提是 MX 处于 Routed 模式（默认）。 但 SGT 在 LAN 端口与 VPN 上的传播默认未启用，必须手工打开。

打标方式与策略：

  • 静态：SSID（Wireless > Access Control → Client IP and VLAN 段）或交换机 access 端口
  • 动态：通过 RADIUS 属性下发，常用于 802.1X（用 ISE 直接下发 SGT，同时覆盖有线与无线）
  • 策略：Organization-wide > Adaptive Policy > Policies → Add Policies，选 Source / Destination Groups 后点 Deny
  • 执行点在 egress 侧；默认允许所有流量；规则基于 SGT 而非 IP 地址
  • 配置层级差异：adaptive policies 在组织级，group policies 在网络级

8.3 Air Marshal（无线 IPS）

  • 合规依据：PCI DSS 4.0 req 11.2.1 要求定期侦测并区分授权/非授权 AP 并告警（p.521）
  • 可告警：接入网络的 rogue AP、伪造我方 SSID/AP 的设备、恶意广播与包洪泛
  • 默认启用（本书少见的默认开着的安全功能）；路径 Wireless > Air Marshal（Monitor）
  • 建议部署带专用扫描射频的 AP；无专用射频的 AP 必须短暂 off-channel（停止服务客户端）才能扫描
  • RF 控制：Wireless > Radio Settings 用 RF profiles 定制信号；对应 NIST 800-53 AC-18(5)（限制边界外无线使用、可校准发射功率）

8.4 Ch8 限制清单（高频踩坑）

  • MR 上被非默认 L3 规则放行的流，不会再次与 L7 规则比对（与 MX 行为不同，p.389）
  • 通过 L7 规则封 HTTPS 不显示 block page；需要阻断页面请用 Secure Connect（p.391）
  • ACL 对本网络内所有交换机生效，无法只对单台交换机生效（p.385）
  • Port isolation 仅本地交换机生效，且 uplink 端口不得启用（p.400）
  • DAI 的 trusted 端口必须先配好，再全局启用（p.405）
  • 本地状态页即使被禁用，通过物理管理口仍可访问（p.413）
  • Sentry Wi-Fi 仅在 SSID 用 Meraki Cloud Authentication 时可用（p.448）
  • MAB 应仅作最后手段，MAC 易被伪造；iOS 默认 Private Wi-Fi Address 会让 MAC 变化，导致 MAB 与手工 group policy 失效（p.458 / p.469）
  • Adaptive Policy Group 只能赋给启用了 RADIUS 的 SSID（即已配 PEAP 或 EAP-TLS）（p.504）
  • SGT 执行不支持在 MX 本身上进行，建议所有客户端接交换机或 AP（p.510）

Ch9 · WAN 安全

9.1 Auto VPN 的工作机制

行为最接近 DMVPN，但依赖 Meraki Cloud 的 VPN Registry（p.528）：

  1. MX 通过 NexTunnel 上的 TCP 443 加密会话发送 Register Request（含自身 IP 与 UDP 端口）
  2. VPN Registry 在 Register Response 中下发对端联络信息 + 两个 16 字符密钥（每个方向一个）
  3. 双方用这些信息建立隧道
拓扑要素行为
支持的拓扑mesh、hub-and-spoke 或混合
hub 之间自动形成全互联
spoke只与 hub 建隧道；spoke 间流量经 hub 中转
扩展性建议用专用 MX 作 hub 并配 VPN Concentrator 模式（Security & SD-WAN > Addressing & VLANs），采用 hub-and-spoke 减少隧道数
站点类型Hub (Mesh)；Exit hub 用于全互联拓扑作默认网关；Spoke 需勾 IPv4 Default Route 才能经 hub 上外网
验证路径Security & SD-WAN > VPN Status（Monitor）悬停 Description 看时延与用量；Exported Subnets 确认发布网段；Appliance Status > Tools > Ping

Client VPN 细节：路径 Security & SD-WAN > Client VPN > IPsec Settings； Hostname 由 Meraki 动态 DNS 自动生成；DNS 可选 Use Umbrella 或 Specify Nameservers； Shared Secret 不要以特殊字符开头或结尾；认证支持 Meraki Cloud / RADIUS / AD，推荐 RADIUS。

AnyConnect 细节：端口默认 443；证书认证需 CA 为 PEM 格式（默认 Disabled）； RADIUS 端口 1812；IPv6 Prefix 需 MX 18.104+； Profile 通过 XML（Secure Client Profile Editor 生成）下发，可配 always-on VPN、登录前启动、备用服务器列表； Session Timeout 默认 None，可选 8 小时 / 1 天 / 7 天 / Custom（以小时计，最大 256 小时）。

9.4 限制 VPN 访问的五种方式

  1. Client Routing（只让指定网段走 VPN）
  2. Default Group Policy
  3. RADIUS Filter-ID
  4. Sentry 策略（Network-wide > Group Policies）
  5. 出站 L3 防火墙规则（Security & SD-WAN > Firewall，源填本地 VPN 子网）

9.6 其他 Ch9 事实

  • Auto VPN 会同时在主/备 WAN 建隧道；非 Meraki VPN 仅用主用 Internet 上行（p.537）
  • AnyConnect 不能与 NAT exceptions（No NAT）同时启用在同一 WAN 上行，且不支持蜂窝接口（需加 MG 网关并设 IP Passthrough）（p.552）
  • Sentry VPN 经 Systems Manager 推送配置，认证方式必须是 Meraki Cloud Authentication，仅支持 Client VPN 不支持 AnyConnect（p.548）
  • 断开远程访问的手段：关闭 Client VPN Server、在 Network-wide > Users 停用账号、或在 Clients 页把 Policy 设为 Block List 后 Apply Policy（p.547）
  • Internet Outages：覆盖 24 小时窗口、每分钟更新，可切 Last 15/30/60 分钟；需 Meraki Insight 或 Secure SD-WAN Plus 许可（p.539）
