流量安全、终端与物理安全

Ch10 是全书篇幅最大、控制措施最密的一章：它把「控制措施」这个主题从传统 MX 防火墙 带到了云原生 Secure Connect 架构。

控制措施主战场 Ch10 p.591–710 Ch11 p.710–753 / Ch12 p.753–793

Ch10 · 流量安全（Secure Connect）

i

架构变化：过去要建 Umbrella SIG IPsec 隧道、装智能体；现在改用 Secure Connect——MX 通过 Dashboard 注册到 Cisco Secure Access， 不再需要 IPsec 隧道，策略与凭据全在 Dashboard 里管（p.612）。

10.1 流量处理顺序（Table 10-1）

序处理环节序处理环节
1Decrypt（解密，按需）5CASB (SaaS API)
2Firewall（L3/L7）6File Inspection（文件检查）
3Web Policy（SWG）7DLP
4Cloud Firewall（IPS）8Encrypt（重新加密）

顺序很重要：Web Policy 在 Cloud Firewall（IPS）之前，而 File Inspection 在 DLP 之前。 另外 MX 的 Layer 3/Layer 7 防火墙仍是第一道关——域名或 IP 被本地规则拒绝时， 流量根本不会到上面这一层（p.594）。

10.2 启用前的先决条件

  • 组织具备 Cisco Secure Connect（SIG）许可
  • 必须先移除已有的 Umbrella SIG 隧道，二者不能共存；此操作不可撤销
  • 需要一个 Cisco Secure Access 账号，并从其中获取 API 凭据
  • Umbrella 侧要建 API 密钥；填错时，去 Organization > License & API Keys 点 Replace API Credentials 覆盖， 若接错了 Umbrella 组织，只能联系支持开 case
  • 三组 API 凭据都只显示一次，务必立即保存
  • 建议先在 Organization > Secure Connect 的网络标签页里，确认所选组织确实是目标组织

10.3 Cloud Firewall（含 IPS）

项细节
IPS 前提必须启用 SSL Decryption，否则 IPS 对加密流量无能为力（p.656）
模式Protection（阻断）/ Detection（仅告警）；可在 Logging 段开启 syslog
自定义 URL 分类用于阻断加密/SSL 流量（用 L7 分类器匹配，如按 URL 含关键字）；IPS 规则本身无法匹配 SSL
坑Cloud Firewall 阻断网站只会静默丢弃，用户看到 "page cannot be displayed"；要友好阻断页必须用 Web Policy（p.648）
规则每条规则可独立设 Action / Protocol / Source / Destination / Logging，并逐条生成 syslog 事件

10.4 Web Policy（SWG）与 HTTPS 检查

  • SSL Decryption：需部署 Root CA 证书（.crt/.cer）到客户端信任库；支持 PEM 导入；Windows 与 Firefox 各有独立的证书库，都要装
  • Decryption Exclusions 用于排除不该解密的站点——PHI 医疗数据应排除（HIPAA，p.676）
  • HTTPS Inspection 会话空闲超时默认 1 小时（1–24 小时）；每会话客户端预留缓冲 10MB（512KB–50MB）
  • Web Policy 规则默认呈灰色未启用，必须手动点 ENABLE RULE（p.661）
  • 分类库可按组织级覆盖（Override），但会改变全组织行为，慎用
  • Google SafeSearch 强制、YouTube 限制模式属 Web Policy 的附加选项（书中未给出对应配置步骤）

10.5 文件检查与宏阻断

项参数 / 事实
文件大小上限单文件最大 32 MB（浏览器上传路径也限 32MB）
Grey List在文件检查设置里维护"不检查"名单（按哈希或按文件名/类型/路径/URL + 文件大小）；已知厂商签名文件有风险，不可盲信
文件类型控制Web Policy > Ruleset Settings → File Type Control，可按 Office / Media / Archive 等大类选具体扩展名；只能在 Web Policy 使用，且依赖 HTTPS inspection
宏阻断Block Macro Files 阻断 .docm / .xlsm / .dotm——对应 Essential Eight 的宏缓解策略；传统文件 .doc/.xls 不能被自动识别阻断
坑不要勾选 Documents 总复选框，否则所有文档都会被阻断——应逐个勾选具体扩展名（p.684）
沙箱Cisco Secure Malware Analytics；沙箱区域（NA/EU）一旦选定不可更改（p.674）
加密/密码保护文件不会被检查；即使送沙箱也无法解密，只会因无法分析而降低评分（示例 score 40 判为 malicious）

10.6 CASB 与 DLP

  • Shadow IT 发现：基于流量自动识别 SaaS 应用与风险等级，可在 Secure Connect > CASB 查看
  • CASB 前提：需启用 HTTPS inspection；SaaS API 方式还需在对应 SaaS 侧授权（如 M365 / Google Workspace）
  • DLP 数据类型：预置多种（信用卡号、社保号、健康信息等），可自定义正则
  • DLP 两种路径：① 浏览器上传走 SWG（HTTPS inspection 后检查）；② SaaS API 直连扫描（云存储 / 邮件 / 协作工具）
  • 加密文件与密码保护的压缩包不会被检查——这是 DLP 的天然盲区
  • 支持的文件格式：PDF、Office 文档等可提取文本的格式；纯图片需 OCR 能力（书中未展开）
  • 合规映射：PCI DSS 3.4.2（防止卡号被未授权转移）、NIST AC-4(4)（检视加密流量）

10.7 Ch10 限制清单

  • 三组 API 凭据只显示一次；接错 Umbrella 组织无法自助更换
  • 移除 Umbrella SIG 隧道不可撤销
  • Cloud Firewall 无友好阻断页；Web Policy 才有
  • 新建 Web Policy 规则默认未启用（灰色）
  • File Type Control 依赖 HTTPS inspection，且仅 Web Policy 可用
  • 沙箱区域选定后不可更改
  • 加密 / 密码保护文件不被检查，DLP 同样盲区

Ch12 · 物理安全

▲

说明：本章讲 MV 摄像头与 MT 传感器的部署与集成，属「物理安全」主题。 书中没有给出 MT 型号命名（MT10/MT20）、温湿度精度数值、门禁系统集成方案。

  • 视频完整性（最实用的细节）：MV 导出的视频文件附带 SHA256 校验值， 可用于证明录像未被篡改——这是「证据链（chain of custody）」的落地手段（p.762）
  • 涉及能力：摄像头部署与视野规划、本地/云端存储、MV Sense 分析、与网络基础设施联动
  • 合规关联：物理访问控制是 PCI DSS / ISO 27001 的独立要求域，但具体条款号书中未逐一标注
  • 书中未涉及：摄像头默认密码策略、固件安全、视频流加密细节、门禁 ACS 集成
