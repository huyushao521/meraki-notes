安全运营 与 用户认证

Ch6 解决「出了事能不能查清」；Ch7 解决「谁能进网络」。两章合起来对应九大主题里的 日志、监控响应、零信任与强认证。

配置级 含页码 Ch6 p.195–287 / Ch7 p.287–384

Ch6 · 安全运营

6.1 三类内置日志（对比表）

日志记录什么保留期入口 / API
Login attempts 成功与失败登录，含 SAML 登录；支持按关键字/IP 过滤，兼容 IPv6 全球统一 14 个月 Organization > Login Attempts（Monitor）
Change log 时间、操作人、Dashboard 位置、变更项、新旧值；含 API 发起的变更 EU 12 个月 / 其他 24 个月 可按 Time/Admin/Network/SSID/Page 排序；支持多条件搜索（空格分隔、不区分大小写），但不能搜时间与日期
Event log 设备事件；不记录管理员登录 全球 12 个月 API getNetworkEvents；Download As 导出 CSV；仅能按时间排序
▲

合规关键点：所有日志只读，无法通过 Dashboard 或 API 修改删除；日志无法关闭； 唯一可配置项是时区。唯一例外：EU 区域实例支持 GDPR 数据删除。

采用保留期而非容量上限，全部日志至少 12 个月 → 满足 PCI DSS 10.5.1。 三类日志在创建组织后默认开启，无需配置（p.196–201）。

6.2 时间同步与时区

  • Meraki Cloud 自动 NTP 同步，无需自建 NTP → 直接满足 PCI DSS 10.6.1（p.196）
  • 默认时区 America – Los Angeles (UTC -7.0 DST)；路径 Network-wide > General > Local Time Zone
  • 时区不能在组织级设置，多网络建议用 Configuration Templates 统一
  • 易错：Change log / Login attempts 页面默认显示 UTC / GMT，Event log 用网络时区（p.197）

6.3 API 使用规则

  • 启用：Organization > Settings > Dashboard API Access 勾选对应项
  • 生成：Organization > API & Webhooks > Generate API Key；明文只显示一次
  • 密钥绑定用户账号；SAML 用户无法生成 API 密钥
  • 最佳实践：用独立只读账号生成密钥，不用于日常管理，该邮箱不要加入其他组织
  • Syslog 在网络级配置（建议入模板），API 密钥是组织级一次配置；Syslog 由设备直接发，API 日志从云端拉
  • Organization ID 显示在每个 Dashboard 页面底部

6.4 Syslog

端口UDP 514
路径Network-wide > General > Reporting（非 Combined 网络在 Logging 段）→ Add a Syslog Server；必须至少选一个 Role
RoleURL、Flows、Event logs（细分 appliance / switch / wireless）、Security events（AMP 拦截、IDS 触发）、Air Marshal events（rogue AP）
Flows 细粒度可按防火墙规则逐条开关：勾选 Security & SD-WAN > Firewall 的 Syslog 列
坑经 AutoVPN 传输若被出站防火墙拦截，需在 Site-to-Site VPN > Organization-wide Settings > Add a Rule 放行
缺陷Flows 不记录不经防火墙的会话（如同交换机下两台终端互访），不如 NetFlow 完整

6.5 NetFlow 与 ETA

  • NetFlow 最新 v9；IPFIX 基于 NetFlow，由 IETF 标准化
  • 支持矩阵：MS390、Catalyst 9300-M/9300L-M/9300X-M 支持 v9 与 IPFIX（IPv4/IPv6）；MX / Z 仅支持 v9
  • ETA（加密流量分析）仅 MS390 与 Catalyst 9300-M 系列（需 UADP ASIC）
  • 由设备直接发出（不经云），无需配置 NAT 或防火墙规则
  • 配置：Network-wide > General > Reporting → Enabled: Send NetFlow Traffic Statistics；填 Collector IP + 端口（示例 UDP 2055）；ETA 需单独填 ETA Collector Port
  • Cisco Telemetry Broker 可采集/转换 NetFlow v5/v9、IPFIX、VPC Flow Logs、NSG Flow Logs

6.6 告警通道

通道参数与配置
Webhook HTTPS POST 到唯一 URL；接收方可为 ServiceNow / Webex / PagerDuty / Jira。 配置 Organization > API & Webhooks > Add Webhook Receiver（Name / URL / Shared Secret）， 再到 Network-wide > Alerts 的 Default Recipients 添加 Webhook: [名称]
SNMP trap 支持 v2c（明文 community string）与 v3（SHA1 认证 + AES 加密）。 trap 源自 Meraki Cloud，需公网 IP；接收端口标准 162。官方推荐优先用 Webhook（443 更易放行）
SNMP 轮询 默认禁止从本地网段外发起，需 Organization > Settings > SNMP 白名单； 只支持 get，不能通过 SNMP 改配置
OID / 端点 支持 .1.3.6.1.2.1.1 与 .1.3.6.1.2.1 下多数 OID； 云端另需 MERAKI-CLOUD-CONTROLLER-MIB；云端查询端点 snmp.meraki.com:16100
SNMP 踩坑 v3 默认预选 SHA + AES128，但设备级轮询实测必须用 DES 作隐私协议，且认证与隐私密码相同； 还需在 Firewall 建入站规则放行 UDP 161

6.7 SIEM 与合规分析

  • Splunk：Splunk Add-on for Cisco Meraki 经 API 采集审计事件、设备状态、告警、变更、认证事件 → NIST 800-53 AU-6；Syslog 入库推荐 Splunk Connect for Syslog（splunkbase app 4740）；输入名不能含空格，audit 类输入回溯 7 天
  • AlgoSec：覆盖 PCI DSS / ISO 27001 / NIST 800-53 / HIPAA / ASD-ISM；建议每日定时分析以留存变更历史
  • ServiceNow：Service Graph Connector for Meraki v1.3.3，支持 Vancouver/Utah/Tokyo；默认导入全部组织，需按 Organization ID 过滤
  • Security Center：Organization > Security Center 汇总 IDS/IPS 与 AMP 事件，支持 Show This Signature/Network/Source Only 与 WHOIS
  • Alerts 页面处于 early preview，需在 Organization > Early Access Opt-in
  • 资产/固件清单：Organization > Inventory（可导出 CSV）；Firmware Upgrades > Schedule Upgrades，状态分 Good / Critical / Warning

Ch7 · 用户认证

7.1 四种方案对比（Table 7-1）

方案MFA适用硬限制步数/难度
Meraki Cloud Auth无 Guest Wi-Fi、小网络、家庭/实验室 按接入方式分别配置（有线/无线/VPN 各一套）；只能配在网络级；密码由管理员生成并以邮件发送；802.1X 用户无法自助改密；不推荐企业 少 / 易
SAML + Duo + EntraCisco Duo（组策略） 各种规模，尤其已用 Entra 仅支持 AnyConnect VPN，不支持有线/无线接入；不支持 Duo inline enrollment 之外……仅 SAML 支持 inline enrollment 约 20 步（已有 SSO）/ 易
RADIUS + ISE + DuoCisco Duo 需最强控制（按时段限制、限制并发登录）、有线无线全要覆盖 配置量大；RADIUS 不支持 inline enrollment，用户须先手工/批量注册 约 60 步 / 中
AD 直连无 已有 AD、有强 Microsoft 技能 仅 MX 支持，MS/MR 接入策略不支持；缺 ISE 排障工具；需配证书；AD 必须位于 MX 本地子网或 VPN 远端子网 少 / 中（排障很难）
◆

书中的选型结论：① AnyConnect VPN → SAML + Duo（同一方案同时覆盖管理员与用户接入，且支持 inline enrollment）； ② client VPN / 有线 / 无线 → RADIUS + ISE + 客户端证书作第二因子（p.381）。

7.2 ISE 前置条件

  • ISE 版本 3.2 patch 1 或更高（示例 3.2.0.542 patch 1）；查版本 Settings > About ISE and Server
  • ISE 须能解析 AD 域名，并与 AD 及所有发 RADIUS 的设备 IP 可达
  • AD 需装 AD DS + DNS；健康检查：dcdiag /test:dns /v /e /dnsbasic /dnsrecordregistration（管理员权限，全部通过）
  • Duo Authentication Proxy 示例版本 6.2.0，可与 AD 同机
  • ISE 以虚机部署；自带 CA 且支持多种第三方 CA；硬件机型内置 TPM

7.3 RADIUS 与 NAD

  • NAD 白名单机制：ISE 只接受已登记设备的 RADIUS 请求；MS / MR / MX 都是 NAD
  • 源 IP 判定（关键）：设备在未参与 site-to-site VPN 的 MX 之后 → 源 IP 是站点 MX 的公网 IP；MX 参与 S2S VPN → 用设备本地 IP
  • NAD 的 Name 不允许空格；IP 处可填网段 / 范围 / 多行 / 0.0.0.0/0
  • 认证端口 1812；IPSEC 设 No；shared secret 必须与 Meraki 设备一致
  • 授权默认动作为 deny，必须另建放行规则（默认 PermitAccess）
  • 仅无线可在 Dashboard 内直接测 RADIUS，无需客户端；但至少需一台已配置 AP，且该 SSID 与相邻设备要有 L2 连通（通常要求 AP 与所连交换机同 VLAN）

7.4 Duo Authentication Proxy 参数

配置段参数
[ad_client]host=（AD IP）、search_dn=（如 DC=lab,DC=local）、search_account_username=、search_account_password=
[radius_server_auto]ikey=、skey=、api_host=、radius_ip_1=（ISE IP）、radius_secret_1=、failmode=（safe=主认证成功即放行；secure=Duo 不可用时拒绝）、client=ad_client、port=1812
[cloud]AD Sync 的 ikey= / skey= / api_host= + 搜索账号

校验：Proxy Manager 点 Validate，SUMMARY 应显示 No issues detected。 可选但推荐：用 authproxy_passwd.exe --whole-config 加密配置里的密码（类比对 IOS 做 service password encryption）。

7.6 本章最关键的限制清单

  • Meraki Cloud 认证无法阻止账号共享，技术上没有手段，只能靠唯一 ID + 限制并发登录 + MFA + 定期改密
  • RADIUS 不支持 Duo inline enrollment → RADIUS 场景必须让用户先完成 Duo 注册（可 Bulk Enroll Users，CSV 格式 username1,email1）
  • SAML 目前只支持 AnyConnect VPN；RADIUS 同时支持 client VPN 与 AnyConnect
  • AD 直连仅 MX 支持；且 LDAP 认证不向 Duo 传客户端 IP，基于 IP 的策略（授权网络、用户位置）全部失效
  • organization-wide RADIUS 目前只适用于有线，无线与 VPN 待后续版本
  • MX 端口级 802.1X 仅支持 MX64/65(W)、MX67/68(C/W)、Z3(C)，且必须在端口级配 RADIUS（组织级不适用）
  • PEAP 是单向信任（只 ISE 出证书）；EAP-TLS 双向证书
